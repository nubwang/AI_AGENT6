# 27 - 进化大脑全域权限与唯一判据（介入全部；唯一原则 = D+1 + 主升浪准确率）

> 用户需求原文："进化大脑要介入全部，一切都是为了提高 D+1 以及主升浪的准确率；进化大脑要有
> 绝对的修改权限读写，唯一需要遵循的原则就是提高 D+1 以及主升浪的准确率；进化大脑可以调整、
> 新增、修改代码。"

本文是这份需求的**设计依据 + 执行台账**。核心结论：
**权限放到最大（全域 + 可新建文件），但"度量本身"必须锁死**——
否则进化大脑可以改口径把"没涨"判成"涨"，"唯一原则"就无法被证明，需求自毁。

---

## 一、改前的真实瓶颈（核查结果）

| 项       | 改前                                                            | 问题                                                |
| -------- | --------------------------------------------------------------- | --------------------------------------------------- |
| 安全模式 | `code_evolution.security_level = "full"`                        | 已无 AST 白名单限制 ✅                              |
| 可改文件 | `code_writer.EVOLVABLE_FILES` **31 个固定白名单**               | 提案与应用**两处硬校验**，白名单外的文件一律拒绝 ❌ |
| 新建文件 | 不支持（`apply_code_patch` 要求文件已存在）                     | 无法新增因子/模块 ❌                                |
| 判据     | `main_metric = {hit_window:5, hit_definition:excess_vs_market}` | 只有 T+5 超额，未体现"D+1 + 主升浪"双判据 ❌        |
| 度量守护 | `protected_files` 5 个文件 + 宪法哈希                           | 方向正确 ✅（保留并收窄为"度量与执行链本体"）       |

## 二、设计：权限最大化的同时让"唯一原则"可被证明

### 2.1 权限域（[`code_writer.py`](../ai-quant-agent/backend/app/agents/code_writer.py:626)）

```
可改：app/**            （全部后端业务代码：推荐链路、回测、Agent、知识库…）
      scripts/**        （全部运维/验证脚本）
      frontend/src/**   （前端源码）
      ★ 并且可以新建文件/模块（mode=new_file）
不可改（PERMISSION_LOCKED，唯一原则的守护）：
      app/agents/evolution_guard.py     守护本体（宪法哈希 / 越权拦截 / 频率监控）
      app/agents/evolution_events.py    事件与审计留痕
      app/agents/evolution_config.py    参数与宪法读写入口
      app/agents/evolution_agent.py     进化主循环
      app/agents/self_improver.py       改动执行链（备份/回滚/生效）
      app/agents/evolution_summarizer.py 归因与提案生成
      scripts/verify_metrics_guard.py   度量口径验证脚本
函数级锁定（METRIC_CORE_FUNCS，文件可改但这些函数不可替换）：
      app/agents/daily_verify.py : _calc_multi      （T+1/T+5 收益与命中计算）
      app/kb/kb_ingest.py        : classify_side    （成功/失败/中性分侧）
```

设计要点：

1. **不再维护白名单**：`is_editable()` 按根目录判定 + 锁定清单排除；`evolvable_files()`
   动态扫描（实测 **199 个可改文件**）。新增模块后**无需改配置**即可被进化介入。
2. **函数级锁定**比文件级更精准：`daily_verify.py` 的**其余部分仍可改**（例如新增归因、
   改启发式），只有"命中判定"这一个函数不可动 —— 既最大化权限，又守住度量。
3. **拒绝理由显式**：任何越界提案都会带原因写进 state 与知识库台账
   （`permission denied: ... 是唯一原则的守护文件`），可审计、可追溯。

### 2.2 唯一判据（`data/evolution_config.json`）

```json
"main_metric": {
  "hit_window": 5,
  "hit_definition": "excess_vs_market",
  "primary": ["t1_hit_rate", "wave_hit_rate"],
  "goal": "唯一原则：提高 D+1 命中率与主升浪命中率",
  "immutable": true
}
```

- `primary` 双指标 = **D+1 命中率**（次日大涨）+ **主升浪命中率**（T+5/波段）
- `immutable: true` + `evolution_guard` 宪法哈希（`main_metric/thresholds/protected_files`）
  → 进化大脑**无法修改判据本身**；改动会被判"篡改"并触发守护
- 本次升级后已执行 `evolution_guard.ensure_baseline()`（人工确认口径升级），
  校验结果 `constitution_ok = True`

### 2.3 让 LLM 真正"知道"自己能改什么

系统提示词（`_CODE_SYSTEM_FULL` / `_BUG_SYSTEM` / 候选文件说明）已改写为：

- 唯一宪法：**提高 D+1 命中率与主升浪命中率**（不再是笼统的"上涨概率"）
- 权限声明：可介入全部业务代码 + 可新建文件/模块（`mode=new_file`，需 `full_content`）
- 边界声明：唯一不可动的是"度量本身"，并说明**原因**（否则提升可被伪造）

## 六、边界与风险（诚实说明）

1. **度量锁定是"唯一原则"的必要条件**，不是保守设计：若可改度量，任何"提升"都不可信。
   若将来确实要改判据（例如加 D+3），必须**人工**改 `main_metric` 并调用
   `evolution_guard.ensure_baseline()` 重新确认基线（本文件即记录了这次人工确认）。
2. **全域权限的风险**：进化大脑现在能改 199 个文件（含前端与脚本）。安全网是既有的
   工程护栏：唯一宪法校验 → 版本化备份 → py_compile → 失败自动回滚 → 待重启生效 →
   效果回滚门（T+1/T+5 基线对比，连续低于基线自动回滚）→ 知识库台账留痕。
3. **建议**：`approval` 保持 `auto` 以发挥"自主介入"的价值；但每次大改后应跑
   `verify_evolution_scope.py` + `verify_evolution_evidence_wiring.py`，确认权限与知识接线未被破坏。
