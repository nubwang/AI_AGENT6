# 28 - 自动生效与午间自进化（免人工重启；每天中午 DeepSeek 闲时自行进化）

> 用户需求原文："进化大脑要自己重启项目，自动生效，不要让我重启再生效，进化大脑每天中午
> deepseek 闲时自动自行。"

本文是**设计依据 + 执行台账**。结论：自动重启的**底层能力早已存在**
（[`self_improver.evolution_apply()`](../ai-quant-agent/backend/app/agents/self_improver.py:294)
以独立进程执行 [`restart_backend.sh`](../ai-quant-agent/scripts/restart_backend.sh:1)，
含避让窗口 + 健康检查 + 失败回滚），缺的是"**谁来按点触发**"与"**改完没人管时的兜底**"。

---

## 一、核查：已有能力 vs 缺失环节

| 环节          | 改前                                                                                              | 缺口                                                             |
| ------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 重启执行器    | ✅ `restart_backend.sh`（避让 09:15-11:30/13:00-15:00、健康检查、失败恢复 `.bak`、成功后清 flag） | —                                                                |
| 重启触发      | ✅ 晚间任务里应用补丁后调用（19:20 / 19:40 / 20:45）                                              | **午间无触发**；若改动来自其他路径（API/手动），需人工点         |
| 兜底守护      | ❌ 无                                                                                             | flag 会一直挂着等人（"待重启代码"提示）                          |
| DeepSeek 闲时 | ✅ `llm_metering.current_period()`：工作日 **12:00-14:00** 与夜间为空闲（**半价**）               | 未与进化调度挂钩，之前把进化排到 19:40（也是空闲，但用户要中午） |
| 开关配置      | 只有 `enabled/approval/max_code_patches_per_day`                                                  | 无午间/自动重启开关                                              |

关键发现：**用户说的"中午 DeepSeek 闲时"正是 12:00-14:00 的 off_peak 半价窗口**，
且 12:00-13:00 不在 A 股交易窗口内 —— 中午进化 + 中午重启完全不打断盘中推荐。

## 二、设计

### 2.1 两个新调度（[`main.py`](../ai-quant-agent/backend/app/main.py:425)）

```
code_evolution_noon   工作日 12:05     ← 午间自进化（DeepSeek 空闲半价 + 非交易窗口）
restart_guard         每 10 分钟        ← 待重启兜底：有改动 + 非窗口 + 未暂停 + 非防抖 → 自动重启
```

- 午间任务：`code_evolution.enabled` → `require_off_peak`（非空闲则跳过并说明省 50%）→
  非交易窗口 → 复用既有 `_code_evolution_job()`（清 pending → 提案 → 应用）→ 立即兜底重启
- 重启守护：**交易窗口内自动跳过**，等 12:00-13:00 或 15:00 后的第一个安全窗口自行生效

### 2.2 纯决策函数（可验证、可审计）

- [`in_trade_window()`](../ai-quant-agent/backend/app/agents/self_improver.py:330)：
  工作日 09:15-11:30 / 13:00-15:00（**与 restart_backend.sh 同一口径**，避免两套窗口打架）
- [`llm_period()`](../ai-quant-agent/backend/app/agents/self_improver.py:339)：转发 `llm_metering.current_period()`
- [`decide_restart()`](../ai-quant-agent/backend/app/agents/self_improver.py:356)：`(有待重启, 交易窗口, 已暂停, 防抖中) → (是否重启, 原因)`
- [`auto_restart_decision()`](../ai-quant-agent/backend/app/agents/self_improver.py:368)：读取真实状态后调用上者
- [`restart_now()`](../ai-quant-agent/backend/app/agents/self_improver.py:404)：带 3 分钟防抖地触发并记录时间戳

### 2.3 配置（`evolution_config.code_evolution`）

```json
"noon_auto_evolve": true,     // 每天中午自动自行进化
"noon_hour": 12, "noon_minute": 5,
"require_off_peak": true,     // 仅 DeepSeek 空闲时段执行（省 50%）
"auto_restart": true          // 改动自动重启生效（守护每 10 分钟兜底）
```

### 2.4 可见可核对

- `GET /system/evolve/auto_apply`（[`system.py`](../ai-quant-agent/backend/app/api/system.py:349)）：
  待重启 / 交易窗口 / DeepSeek 时段 / 守护判定与原因 / 午间计划
- 前端进化中心：权限告示下方新增"自动生效"告示（[`Evolution.vue`](../ai-quant-agent/frontend/src/views/Evolution.vue:1042)）

## 四·五、全天时间表（新增约束：用户 19:00 下班关机）

> 用户补充："进化大脑最好都安排在中午，我下午七点都下班了，都关机了。"
> 因此**所有不依赖当日数据的进化/学习任务全部迁到午间**（12:00-14:00 同时是
> DeepSeek 空闲半价窗口 + 非交易窗口），依赖当日收盘数据的排到 17:00-18:55（下班前）。

| 时间                 | 任务                     | 说明                                                 |
| -------------------- | ------------------------ | ---------------------------------------------------- |
| 08:00                | 政策知识库采集           | 早上开机后即可（非进化核心）                         |
| **12:05**            | **午间自进化**（工作日） | 提案 → 应用 → 自动重启                               |
| **12:20 / 13:50**    | **报错监控 → 修 bug**    | 原 19:20 / 20:45（关机后跑不到）                     |
| **12:35**（周日）    | **每周批次应用**         | 原 19:50                                             |
| **12:40**（每 3 天） | 懒评估                   | 原 18:40                                             |
| **12:45**            | 知识库维护               | 原 19:00                                             |
| **12:50**            | 统一学习层（历史）       | 原 19:10                                             |
| **12:55**            | 待确认提案清理           | 原 18:50                                             |
| **13:30**            | 自进化（第二次机会）     | 原 19:40；12:05 被跳过时兜底                         |
| 全部时段             | **自动重启守护**         | 每 10 分钟；交易窗口内自动跳过                       |
| 17:30                | 数据采集                 | 依赖 Tushare 当日数据到达                            |
| 18:00                | 政策晚间补采             | 覆盖晚间发文                                         |
| 18:10                | 守护巡检                 | 需当日验证后的指标                                   |
| 18:20                | 次日自我验证             | 需当日收盘数据                                       |
| 18:30                | 影子期结算               | 需当日数据                                           |
| **18:45**            | 回测自动验证             | 原 20:00（关机后跑不到）                             |
| **18:50**            | 统一学习层（当日增量）   | 采集后补跑，保证当日数据也被学到                     |
| 18:55                | 清理                     | 已并入 12:55                                         |
| 21:00                | 采集兜底补采             | 唯一 >19:00 的任务（若机器仍开机则补采，失败有重试） |

**校验**：`verify_auto_evolution.py` 新增"时间窗口合规"断言 ——
除数据采集类外，**不允许任何任务排在 19:00 后**；进化类任务必须落在 12:00-14:00 或 ≤18:00（实测 31/31 通过）。

## 五、完整闭环（现在无需任何人工）

```
每天 12:05（工作日）
  ├─ 判定：enabled? → off_peak?（半价）→ 非交易窗口?          [任一不满足则跳过并记录原因]
  ├─ 清遗留 pending → 生成提案 → 应用（唯一宪法校验/备份/编译/回滚门）
  ├─ 若有待重启改动 → 立即触发 restart_backend.sh（独立进程，不 kill 自己）
  └─ 兜底：_restart_guard_job 每 10 分钟兜住任何"待重启但没触发"的情况
        └─ 交易窗口内自动跳过 → 12:00-13:00 或 15:00 后自行生效
```

## 七、边界（诚实说明）

1. **交易窗口不重启**是刻意保留的：盘中重启会打断推荐与回测（且当前 09:15-11:30/13:00-15:00
   正是行情连续竞价）。午间 12:05 与 15:00 后重启**零影响**。
2. **自动重启不等于盲目生效**：仍走完整护栏（备份 → py_compile → 健康检查 → 失败自动回滚 `.bak` →
   效果回滚门：T+1/T+5 基线连续低于阈值自动回滚）。
3. 若某天中午希望**不**自进化（例如正在手工观察某次改动效果），改
   `code_evolution.noon_auto_evolve=false` 即可；或临时 `pause` 进化（守护暂停期间不会重启）。
