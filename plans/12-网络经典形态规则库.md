# 规划 12：规则形态库（网络经典 + 系统自总结）+ 回测验证 + 每日推荐筛选层

> 本文档对齐 [`04-回测引擎.md`](plans/04-回测引擎.md)（3 倍段召回/特征/条件概率/模式库）与
> [`09-每日推荐详细规划.md`](plans/09-每日推荐详细规划.md)（推荐流水线）。
>
> **核心思想（用户明确）**：
>
> 1. **统一"规则形态"概念**：网络经典形态（老鸭头、仙人指路…）与系统在回测中**模仿它们自己总结出的规则形态**，
>    本质相同——都是"**最近几天的形态 → 次日（T+1）上涨概率**"的可编码规则。两者**归一为同一套规则框架**。
> 2. **回测检验 + 硬淘汰**：所有规则形态（含网络经典）都必须在回测中验证 T+1 上涨概率，
>    **回测结束后，次日上涨概率 < 45% 的规则形态一律删除**，只保留"次日上涨概率高于门槛"的规则。
> 3. **双信号等权融合为每日推荐筛选层**：规则形态（几天尺度）与现有 20 天形态向量（[`MATCH_FEATURES`](ai-quant-agent/backend/app/backtest/feature_extractor.py:100)）
>    时间尺度不同、职责不同、**权重相同（各 50%）**——规则形态作为第二个信号维度，与 20 天向量共同决定最终推荐排序。
>    文档版本 v4.0

## 一、背景与目标

### 1.1 现状

- 现有每日推荐（[`daily_scan.py`](ai-quant-agent/backend/app/backtest/daily_scan.py:51)）基于**20 天形态向量**：3 倍模式库相似度 → 条件概率（T+5 口径）→ 反向排除
- 20 天向量回答"会不会成为波段牛股"；**不回答"明天会不会涨"**
- 已接入最佳入场点（[`entry_analyzer.py`](ai-quant-agent/backend/app/backtest/entry_analyzer.py)）与入场指引（[`entry_guidance.json`](ai-quant-agent/backend/data/entry_guidance.json)）

### 1.2 目标（用户需求）

1. **统一规则形态框架**：网络经典形态 + 系统自总结形态，归一为同一套 `RuleForm`（几天形态 → T+1 上涨概率）
2. **回测验证 + 45% 硬门槛**：所有规则形态回测验证 T+1 次日上涨概率；**< 45% 的删除**
3. **系统自总结规则**：在回测中模仿网络经典形态的"编码规则"方式，从 3 倍股数据自动总结出新的几天形态规则（可解释、可编码、非黑盒）
4. **每日推荐双信号等权融合**：规则形态与 20 天向量**各占 50% 权重**，共同决定推荐排序，提高次日上涨概率筛选

### 1.3 核心原则

> **"网络说会涨" ≠ "数据说会涨"。**
> 所有规则形态（网络经典 + 系统自总结）一律统一归一、统一回测验证；
> **次日上涨概率 < 45% 的规则形态在回测结束后直接删除**（A 股 T+1 次日上涨全市场基线约 45~55%，45% 即"高于随机抛硬币"）。

## 三、规则形态统一框架（RuleForm）

### 3.1 统一概念

> **所有"规则形态"都是同一类东西**：一个**可编码的判定规则**，作用于**最近 N 天（3~10 日）的 K 线**，
> 命中时预示"次日（T+1）上涨概率"。网络经典形态与系统自总结形态只是"来源不同"，**schema 完全一致**。

```python
@dataclass
class RuleForm:
    key: str                    # 唯一标识：网络经典 "laoyatou" / 自总结 "auto_0001"
    name: str                   # 可读名："老鸭头" / "放量突破+均线多头"
    source: str                 # "network"（网络经典）/ "auto"（系统自总结）
    form_type: str              # 所属启动形态（A/B/C/D/U），用于映射入场指引 entry_guidance
    lookback_days: int          # 判定窗口（最近 N 天，如 3~10）
    description: str            # 人类可读描述（可解释性）
    hit_rate_t1: float = 0.0    # 回测验证的次日上涨率（核心指标）
    samples: int = 0            # 样本量
    verified: bool = False      # 是否通过 45% 门槛 + 显著性 + 样本外

    def detect(self, df, idx) -> bool:  # 只用 idx 及之前数据判定（防未来函数）
        ...
```

> **form_type 字段（v4.0 新增）**：用于把规则映射到 [`entry_guidance.json`](ai-quant-agent/backend/data/entry_guidance.json)（该文件按 A/B/C/D 分组固化最佳入场，[`build_entry_guidance`](ai-quant-agent/backend/app/backtest/entry_analyzer.py:267)），解决"规则 key ≠ form_type key"的映射问题。

### 3.2 两类来源，同一框架

| 来源                    | 说明                                 | 例子                                                                                                                      |
| ----------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| **网络经典（network）** | 人工定义的可编码规则，先验候选       | 老鸭头、仙人指路、出水芙蓉、红三兵、多方炮、早晨之星、金针探底、双底、头肩底、均线多头、缩量回踩…（看跌形态用于反向排除） |
| **系统自总结（auto）**  | 回测中模仿网络经典方式自动挖掘的规则 | "放量阳线突破 5 日新高 + RSI 60~80 + 量能 1.5 倍" 等可解释规则                                                            |

## 四、系统自总结规则（模仿网络经典方式，非黑盒）

### 4.1 与"聚类自发现"的区别

> 用户要求：自总结规则要**像网络经典形态那样**——是**可编码、可解释的规则**（如"近 3 日放量 + 突破前高"），
> 而不是黑盒聚类。因此用**规则学习/频繁模式挖掘**，不用（或仅辅助）KMeans。

### 4.2 自总结方法（规则学习）

1. **样本**：全市场 3 倍股样本 + 普通日样本（扩样，见 [`plans/04`](plans/04-回测引擎.md:1473)）
2. **候选特征**：最近 3~10 天的可解释形态特征（放量倍数、突破前高/平台、均线关系、K 线实体/影线比例、连续阳线数、RSI 区间、涨停封板…）
3. **规则挖掘**：对每个候选特征（或两两组合）做**分位切分 + 条件概率统计**（复用 [`threshold_analyzer.py`](ai-quant-agent/backend/app/backtest/threshold_analyzer.py) 的机制），找出"命中该条件 → T+1 上涨率 ≥ 45% 且样本量足够"的规则
4. **规则命名**：自动生成可读描述（如 "近3日放量突破5日新高 且 RSI≥60"）
5. **规则相关性去重（v4.0 新增）**：对高度相关的规则（如"老鸭头"≈"均线多头"）合并为规则族或只保留 `lift_t1` 最高者，避免融合时重复计分
6. **与网络经典的关系**：系统自总结可能恰好发现"类似老鸭头"的规则（归为同一规则或标注等价），也可能发现网络之外的新规则——**都进统一框架，接受同样验证**

### 4.3 看跌规则（反向排除用）

同样用规则学习挖"命中 → T+1 下跌概率高"的看跌规则，**在每日推荐融合时对 `rule_prob` 做负向抑制**（见 6.4 Step 2）。

## 五、回测验证 + 45% 硬淘汰

### 5.1 样本来源（口径 1：与现有推荐同源，推荐）

- **主样本**：现有回测产出的 3 倍股候选样本（与每日推荐同源，直接增强现有榜单）
- **扩样**：补充全市场普通日抽样，保证每个规则形态样本量充足（至少 30~50 个可交易样本）
- **结局口径（唯一）**：`hit_t1` = T+1 收盘 > 当日收盘（次日上涨）；辅助 `hit_t1_2pct` = T+1 > 2%
- **样本有偏说明（v4.0 新增）**：主样本来自 3 倍股候选（启动点采样），`hit_rate_t1` 可能略高于全市场真实水平（强者恒强）。此偏差在"口径 1"下可接受（目标是增强现有榜单），但排行榜需标注 `sample_source`（如 "3x_candidates" / "market_sample"）供审计。

### 5.2 验证流程

1. 对每个 `RuleForm`，在样本上跑 `detect` → 命中样本统计 `hit_rate_t1`
2. **45% 硬门槛**：`hit_rate_t1 < 0.45` 的规则形态**直接删除**（回测结束后从规则库移除）
   - 阈值可配置（默认 0.45，用户明确）
3. **相对提升门槛（v4.0 补充）**：除绝对 45% 外，要求 `hit_rate_t1` ≥ 同期全市场基线（`baseline_t1`），避免"牛市里什么都高"——即规则必须不劣于随机
4. **样本量下限**：< 30 个可交易样本 → 标记"样本不足"，不进入推荐
5. **显著性**：`hit_rate_t1` vs 同期全市场基线，McNemar/二项检验显著
6. **样本外**：Walk-Forward 时间切分，前 80% 训练选规则、后 20% 验证，防止过拟合
7. **无规则幸存兜底（v4.0 新增）**：若全部规则都被删除（幸存 < 3 条），系统回退为"仅 20 天向量"模式（即现有行为），并在日志/前端提示"规则库未产生有效规则"
8. 通过 → `verified=true` 固化进 [`form_leaderboard.json`](ai-quant-agent/backend/data/form_leaderboard.json)

## 六、每日推荐筛选层（双信号等权融合）

> 🎯 **用户明确**：规则形态与现有 20 天向量**权重一样、同等重要**——规则形态不是"加分项"，而是与 20 天向量**并列的第二个信号维度**，两者共同决定最终推荐排序。这才是真正的"无损叠加、一样重要"。

### 6.1 与 20 天向量的关系（双信号等权）

|          | 信号 1：现有 20 天向量层     | 信号 2：规则形态层（新增）            |
| -------- | ---------------------------- | ------------------------------------- |
| 时间尺度 | T0 前 20 天形态背景（33 维） | 最近 3~10 天的短线确认                |
| 职责     | 决定"会不会成为波段牛股"     | 决定"**明天会不会涨**"（买入点确认）  |
| 信号方向 | 波段/趋势（T+5 口径）        | 次日短线（T+1 口径）                  |
| **权重** | **默认 0.5（可配置）**       | **默认 0.5（可配置，与信号 1 相等）** |
| 叠加方式 | —                            | **独立检测、独立打分、等权融合**      |

### 6.2 流程改造（[`daily_scan.py`](ai-quant-agent/backend/app/backtest/daily_scan.py:51)）

1. **信号 1（现有 20 天向量层，不动）**：每只候选照常打分 → `up_probability`（模式库相似度 × 条件概率 × 负向抑制）
2. **信号 2（规则形态层，新增）**：在 `end_idx` 跑所有 `verified=true` 的 `RuleForm.detect`，得到命中规则列表，合成次日概率（含看跌抑制，见 6.4 Step 2）
3. **等权融合（核心）**：两个信号各自归一化到 0~1 后**等权合成**，作为主排序分（`final_score`，见 6.4 Step 4）
4. **排序口径**：榜单按 `final_score`（融合综合分）降序，作为**主榜单**；现有 `up_probability`（T+5 口径）作为并列参考列展示
5. **入场建议**：命中规则 → 按其 `form_type` 调 [`entry_guidance.json`](ai-quant-agent/backend/data/entry_guidance.json) 给出买入点建议（v4.0：通过 `RuleForm.form_type` 映射）

> **口径说明（修正）**：不采用"`up_probability × (1+α×加分)`"——那会让规则形态只起小权重补充。改为**两个信号各自归一化后等权相加**，规则形态与 20 天向量对最终排序的影响权重相同，真正"一样重要"。

### 6.3 前端展示（[`Recommend.vue`](ai-quant-agent/frontend/src/views/Recommend.vue)）

- 推荐表新增"命中规则"列：展示老鸭头 / auto_0012 等标签 + **次日上涨率徽标** + 该股 `rule_prob`
- 展示两个信号分：`波段分（20天信号）` 与 `规则分（次日信号）`（权重各 50%），融合得 `final_score`
- **文案说明（v4.0）**：明确标注 `final_score` 是"波段+次日融合综合分"，`up_probability` 是"波段分"，避免用户混淆两套概率
- 详情：规则描述 + 样本数 + T+1 上涨率 + 入场建议

### 6.4 等权融合实现细节（完整规格）

> 本小节为 P5 实现时的精确规格，明确"双信号等权"如何落地，避免实现偏差。

**Step 1：信号 1 —— 20 天向量分（沿用现有逻辑，不改）**

每只候选股计算现有 `up_probability`（[`daily_scan.py`](ai-quant-agent/backend/app/backtest/daily_scan.py:167)）：

```text
up_probability = 条件概率 prob × (1 - LAMBDA_EXCLUDE × 负向相似度 neg_sim)
```

**Step 2：信号 2 —— 规则形态分（新增，含看跌抑制）**

在 `end_idx` 对所有 `verified=true` 的规则跑 `detect`，得到**看涨命中规则集合 H** 与**看跌命中规则集合 N**：

```text
# 看涨部分（命中多条：按规则权重加权平均；未命中任何看涨规则 → 用全市场 baseline_t1 作中性值）
rule_pos = Σ_{r∈H} w_r × r.hit_rate_t1  /  Σ_{r∈H} w_r
         = baseline_t1                                # H 为空时

# 看跌抑制（v4.0：命中看跌规则 → 压低信号 2）
rule_prob = rule_pos × (1 - λ_neg × Σ_{n∈N} w_n × n.fall_rate_t1)
           # fall_rate_t1 = 该看跌规则命中的 T+1 下跌率；λ_neg 默认 0.3，可配置
```

- 规则权重 `w_r`：默认 = 规则的 `lift_t1`（相对基线提升）× 样本量开方（防止小样本高概率喧宾夺主）；可配置
- 中性值 `baseline_t1`：来自 [`form_leaderboard.json`](ai-quant-agent/backend/data/form_leaderboard.json) 的 `baseline_t1`（约 0.45~0.55）

**Step 3：归一化（保证两信号量纲可比）**

因为 `up_probability`（T+5 波段概率，常 0.3~0.7）与 `rule_prob`（T+1 次日概率，常 0.4~0.6）分布不同，**不能直接相加**，需各自归一化到 0~1：

```text
norm_up    = min-max 缩放：基于当日全部候选的 up_probability 分位（如 5%~95% 映射到 0~1）
norm_rule  = 线性映射：rule_prob 相对 [baseline_t1, max(0.7, 基线+0.15)] 区间映射到 0~1
             （rule_prob ≤ baseline_t1 → 0；rule_prob ≥ 上界 → 1；之间线性）
             # 上界可配置（v4.0 说明：不再硬编码 0.9，随基线自适应）
```

**Step 4：等权融合（核心，权重相等）**

```text
final_score = w1 × norm_up + w2 × norm_rule
默认 w1 = w2 = 0.5   # 两信号同等重要，用户明确要求
```

- 权重在配置中可调（如 0.4/0.6），但**默认必须等权**
- 结果 `final_score` ∈ [0, 1]，为**融合综合分**（波段 + 次日），**非纯 T+1 概率**（v4.0 口径澄清）

**Step 5：排序与输出**

- 榜单按 `final_score` 降序，作为主榜单
- 每条候选保留三个分：`up_probability`（T+5 波段）、`rule_prob`（T+1 规则）、`final_score`（融合），前端并列展示
- 现有 T+5 榜单（仅按 `up_probability`）作为第二套榜单保留，不删除

**Step 6：与风险过滤 / Agent 精筛的关系**

- 风险过滤（[`check_risk`](ai-quant-agent/backend/app/backtest/risk_filter.py)）仍在最前，不通过直接排除（两信号都不参与）
- Agent 精筛（[`agents`](ai-quant-agent/backend/app/agents)）在融合排序之后，对 `final_score` 榜单做 LLM 精筛，两信号分作为输入特征传入

**Step 7：性能优化（v4.0 新增）**

- 全市场 × 每候选 × 30+ 规则 detect 开销大。优化：**共享一次窗口特征预计算**（均线/RSI/量比只算一次，规则只做阈值判断）；仅对进入候选池的股票跑 detect（不与 20 天向量层并行的股票跳过）

**口径红线（避免回归"加分式"）**

- ❌ 禁止：`final_score = up_probability × (1 + α×Σ规则加分)`（α 小则规则形态被边缘化）
- ✅ 采用：两个信号**各自归一化后等权相加**（w1=w2=0.5），规则形态对排序影响与 20 天向量相同

## 九、风险与对策

| 风险                               | 对策                                                                |
| ---------------------------------- | ------------------------------------------------------------------- |
| 45% 门槛在牛市失真（全市场都高）   | 追加"不劣于同期基线"要求（hit_rate_t1 ≥ baseline_t1），不只绝对 45% |
| 规则样本过少                       | 扩样 + 样本量下限 30；不足标记"样本不足"不进入推荐                  |
| 过拟合（自总结规则对历史过度拟合） | Walk-Forward 样本外验证 + 规则可解释性人工复核 + 相关性去重         |
| 规则重叠（老鸭头 ≈ auto_0012）     | 相关性去重：保留 lift 最高或合并规则族；权重按 lift 与样本量        |
| 命中规则但买不进（一字板）         | 沿用 tradeable 标记                                                 |
| 无规则幸存（全部 < 45%）           | 回退"仅 20 天向量"模式 + 日志/前端提示规则库未生效                  |
| 看跌规则误伤正样本                 | 看跌抑制系数 λ_neg 默认 0.3，可配置，不过度压制                     |

## 十、验收标准

1. `RuleForm` 统一框架覆盖网络经典 + 系统自总结，schema 一致（含 form_type）、可编码可验证
2. 回测产出 [`form_leaderboard.json`](ai-quant-agent/backend/data/form_leaderboard.json)：**所有保留规则 `hit_rate_t1 ≥ 0.45` 且 ≥ 基线**，被删规则有审计记录
3. 系统能自动总结出至少 5 条可解释的规则形态（非黑盒），且已做相关性去重
4. 每日推荐**双信号等权融合**：20 天向量信号与规则形态信号各占 50%（可配置），榜单按 `final_score`（融合综合分）降序，展示"命中规则 + 次日上涨率 + 入场建议"，含看跌抑制
5. 无规则幸存时系统正常回退为"仅 20 天向量"模式
6. 全程无未来函数：规则 detect 只用 idx 及之前数据；结局只统计 T+1
