# 规划 19：进化大脑"控制回测" + 回测环节归因 —— 考虑"是不是回测的问题"，极致提升上涨率

## 一、用户核心想法（原文提炼）

> "进化大脑也要有控制回测的功能，也要考虑是不是回测的问题，是不是回测逻辑问题还是啥问题，
> 这个进化大脑也要考虑，极致的利用各种办法增加上涨率"

三要素：

1. **控制回测**：进化大脑能主动触发回测 / 查状态 / 读结果（验证其回测改动效果）；
2. **回测环节归因**：失效归因时要考虑"是不是回测逻辑的问题"（回测逻辑失效 / 回测产物与每日推荐脱节），而不只是每日推荐侧环节；
3. **极致提升上涨率**：综合 次日验证归因 + 环节归因（含回测侧）+ 回测健康诊断 + 代码进化 多手段闭环。

## 二、现状与差距

- 已有：`code_writer` 可改回测文件（EVOLVABLE_FILES）；`daily_verify` 环节归因 STAGE_MAP；`system_map` 回测图谱。
- 差距：
  - 进化大脑**不能主动运行回测**（只能改回测代码，改完无法验证效果）；
  - `STAGE_MAP` 回测侧只有笼统 `backtest_product` 一个环节，无法定位"回测逻辑问题"具体出在结局分流/特征拟合/模式库/条件表/归一化哪一环；
  - 进化大脑没有"回测命中 vs 实盘命中"的对照，不知道是不是回测产物没传导到每日推荐。

## 三、实现

### 3.1 [`backtest_ctl.py`](ai-quant-agent/backend/app/agents/backtest_ctl.py:1)（新增）—— 进化大脑"控制回测"

| 能力                        | 说明                                                        |
| --------------------------- | ----------------------------------------------------------- |
| `is_running()` / `status()` | 回测是否在跑/状态（复用 backtest API 状态机）               |
| `trigger_backtest()`        | 触发回测（后台线程；冷却 6h + 不抢占已运行任务 + 可 force） |
| `latest_result()`           | 读最新回测报告（backtest_latest.json）                      |
| `backtest_health()`         | **回测健康诊断**：对比回测命中率 vs 每日推荐实盘命中率      |

`backtest_health()` 判定（"是不是回测的问题"）：

| verdict             | 含义                                | 优化方向                                                                                    |
| ------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------- |
| `backtest_decouple` | 回测准但实盘低 → **回测产物未传导** | 查 daily_scan 加载 probability_table/condition_table/normalizer 口径、vector_store 特征同源 |
| `backtest_failure`  | 回测命中率本身低 → **回测逻辑失效** | 查 outcome_tracker 结局分流 / feature_extractor 特征 / pattern_miner 模式库                 |
| `market_issue`      | 都低 → 系统性/市场                  | 结合 market 环节归因、freshness 漂移                                                        |
| `normal`            | 实盘达标                            | 维持                                                                                        |
| `insufficient`      | 数据不足                            | 待积累                                                                                      |

> 实测（2026-08）：`backtest_decouple` —— 回测 accuracy=0.80，实盘次日 T+1 命中=0.10，差值 0.70，明确指向回测产物与每日推荐脱节。

### 3.2 [`daily_verify.py`](ai-quant-agent/backend/app/agents/daily_verify.py:265) —— STAGE_MAP 细化回测环节

新增回测侧可归因环节：
`backtest_outcome`（结局分流）、`backtest_feature`（特征拟合）、`backtest_pattern`（模式库构建）、
`backtest_condition`（条件概率表）、`backtest_normalizer`（归一化参数）、`backtest_product`（产物脱节）。
归因模板提示 LLM "优先判断是不是回测侧环节的问题"。

### 3.3 进化大脑信息接入

- [`evolution_summarizer.py`](ai-quant-agent/backend/app/agents/evolution_summarizer.py:90)：L0 新增 `backtest` 字段 + 文本行"回测诊断[verdict]: ... → 建议..."；
- [`code_writer.py`](ai-quant-agent/backend/app/agents/code_writer.py:310)：`_CODE_SYSTEM_FULL` 明确"若回测诊断显示 decouple/failure 必须优先处理回测侧问题"；`_propose_full` 注入回测诊断；补丁返回 `backtest_affected`。

### 3.4 自动回测验证闭环（[`main.py`](ai-quant-agent/backend/app/main.py)）

- 进化大脑应用**回测文件**补丁 → 写"待回测验证"标记 `pending_backtest_verify.json`；
- 次日 12:10 `_daily_verify_job` 检测标记 → 系统空闲时自动 `backtest_ctl.trigger_backtest()` 重跑回测 → 更新 backtest_latest.json → 回测健康诊断随之刷新（进化大脑据此判断改动是否有效）。

### 3.5 API（[`system.py`](ai-quant-agent/backend/app/api/system.py:233)）

- `GET /api/v1/system/evolve/backtest/diag` 回测健康诊断
- `GET /api/v1/system/evolve/backtest/status` 回测状态
- `POST /api/v1/system/evolve/backtest/run` 触发回测（进化大脑/人工控制）

## 四、闭环

```
每日推荐实盘(T+1命中) ──┐
                        ├─→ backtest_health 诊断（decouple/failure/…）
回测命中率(accuracy) ───┘          │
                                   ▼
                   进化大脑 L0（次日验证归因 + 环节归因含回测侧 + 回测诊断）
                                   │
                                   ▼
              code_writer 改回测/推荐逻辑（优先问题最大环节/回测侧）
                                   │
                                   ├─→ 重启生效 → "待回测验证"标记
                                   └─→ 次日自动重跑回测 → 诊断更新 → 循环
```

## 七、信息滞后修正（用户核心诉求：晚上才有数据、次日才能买入）

**问题（前瞻偏移 / look-ahead bias）**：每日推荐基于推荐日(D)收盘数据在晚上生成，D 日收盘后已无法买入，实际只能 **D+1 日买入**。旧口径以 D 收盘为基准，把"D→D+1"这段用户吃不到的涨幅当推荐成绩 → 严重高估系统能力、误导进化。

**修正**：验证/反思收益统一改为 **D+1 买入口径**：

- 基准 = **D+1 收盘**（用户买入价）；
- `t1` = D+1 买入持有 1 日（D+2 收盘 vs D+1 收盘）；`t5`/`t20` 同理（持有 5/20 日）；
- 覆盖 [`daily_verify._calc_multi()`](ai-quant-agent/backend/app/agents/daily_verify.py:105) 与 [`reflect_agent._calc_outcome()`](ai-quant-agent/backend/app/agents/reflect_agent.py:83)；
- `backfill_t1(force=True)` 全量对齐新旧口径（避免混合）；
- 归因模板 / L0 摘要标注"（D+1 买入持有 1 日）"；
- [`backtest_ctl`](ai-quant-agent/backend/app/agents/backtest_ctl.py:1) 诊断注明：每日推荐为 D+1 买入口径、回测为 T0 收盘买入口径，回测-实盘差值部分含口径差（进化大脑据此判断，不把差值全归因于回测脱节）。

**注意**：修正后，验证天然需要更晚的数据（买入日 D+1 及持有期 D+2…），最新推荐的 t1 会因数据未到返回 None、由后续轮次自动补回填；这也与"当天验证前天的自我验证"（次日 12:10 跑）完全契合。
